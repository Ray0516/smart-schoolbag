# 完整交接：現況、架構與下一步

交接日期：2026-11-05（臺灣）。版本：韌體 v1.5.0、App 1.5.0+15。這份庫是工作來源快照，不在交接時偷偷更換硬體行為。

## 接手目標

學生以手機設定任意課程及物品，將書籍與其他物品分類，安排星期一至日的要帶清單；同步後裝置離線顯示課表、清單、日期記事及便利貼。RC522 近距離掃描已配對標籤時勾選物品，OK 也可手動勾選。GPS 顯示實際定位狀態，沒有 fix 不顯示假座標。

RFID 不是整個書包內容感測器：RC522 只能逐件靠近掃描，掃描成功不代表物品一直留在書包內。標籤名稱由手機資料庫／UID 對照提供，現在不是從每張卡的 NDEF 名稱欄讀取。手機寫實體 RFID 標籤內容仍未完成；手機現有配對是命令 S3 讀卡後保存 UID。需要通用跨裝置名稱時，必須另外定義卡片格式與相容性，不可冒充已完成。

## 韌體結構

EPaperTest.ino 只呼叫 epaper_test::begin/poll。EPaperTestApp.h 集中 UI、RFID、NVS、BLE、HTTP、按鍵與深睡；PanelConfig.h 是接線及面板配置；GpsSupport.h 持續讀取 UART/NMEA；ChineseText/ChineseGlyphs/RfidText 是字庫與名稱呈現。內嵌驅動位於 src/MFRC522、src/TinyGPSPlus。

SPI 共用給 EPD 和 RC522；不要讓網路回呼直接佔用共用 SPI。BLE 資料先排隊，主流程處理命令；NVS 失敗需回 ERR。電子紙刷新是實體面板波形，不能只刪除延遲就保證變快；目前同頁一次整頁局刷，切頁全刷，可設定定期全刷頻率或只切頁全刷。

## 手機結構

main.dart 集中資料類別 BagItem/Lesson/CalendarEntry、BagStore、BagBle（歷史名稱，現也管理 Wi-Fi）、同步與各頁面。先用 rg 找定義再改，不要只憑名稱以為是 BLE 專用。MainActivity.kt 是 Android 平台整合；Android 清單和網路設定必須一起保留。UI 簡約、繁體中文，主要分頁為今日、課表、記事、更多。

BagItem 存 name/tag/分類/完成星期等資料。dayItemOverrides 保存每星期從物品資料庫勾選的清單；明確空清單必須保持空，不能回退課表推導。沒有 override 才由課程／既有規則／日期事件推導。重新命名與刪除要更新所有引用。七日完成狀態不可互相覆蓋。

便利貼本機為標題加換行加內容；通訊改成 ASCII RS 分隔，UTF-8 最大 120 bytes、最多五則。課表每日最多 12 節。設定同步、日期切換、改名／刪除、連線中斷及同時刷卡是主要風險點。

## 同步模型與風險

主要為書包 AP 的 HTTP，沒有路由到家用 Wi-Fi 或雲端。手機資料是課表／名稱／排序的來源，裝置回報 UID／勾選狀態；對應索引與名稱要核對，避免舊資料覆寫改名項。autoSync 使用資料指紋、debounce、互斥旗標，前景修改及回前景後同步，每 10 秒重試；配對等待暫停自動推送。

請優先驗證：冷啟動是否先拉取舊狀態而覆寫本機新資料；未變更資料的指紋是否包含所有要同步欄位；配對同張卡是否一直等待；超時後是否釋放 busy 旗標；切換星期是否套錯完成遮罩；同步中斷後是否保留上一份資料；空課表／清空便利貼是否能傳到裝置。這些是驗收重點，不代表已重現全部缺陷。

## 接手優先順序

1. 在乾淨環境重跑建置與現有測試；先保持行為，避免一邊重構一邊猜測。
2. 手機連書包 AP，逐項驗證自動同步與斷線重試，特別是便利貼讀回、七日清單、空值及改名。
3. 實機五鍵與 RFID 重複刷卡回歸；記錄實際刷新時間與殘影，再核對面板型號。
4. 驗證長按到門檻即關機、持續按住不反覆開關機、RTC 和手動星期保留。
5. 實作尚缺需求前先定義資料／協定：放學帶回清單、出門缺項摘要、完整週表顯示、卡片名稱格式、拍照黑白掃描等，參考 FEATURES。
6. 最後才把單檔 main.dart、EPaperTestApp.h 拆模組，所有遷移保留測試。
